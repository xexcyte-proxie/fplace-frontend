# Route-Guided Physical Walk Demo

Enable the existing `VITE_PHYSICAL_WALK_DEMO=1` developer flag. Select start and destination on a single floor in Riverside Stadium, then use the route normally. The floating demo/log controls are hidden by default (`VITE_HIDE_PHYSICAL_WALK_CONTROLS=1`); the walking simulation still starts automatically. **Route-Guided Physical Walk Demo · simulated route-guided walk** starts automatically when a route is selected. Developer diagnostics can be explicitly restored with `VITE_HIDE_PHYSICAL_WALK_CONTROLS=0`. Switching modes starts a new origin capture. Raw Physical Walk Demo remains available in the mode selector and remains unsnapped for diagnostic comparison. Physical coordinates are not navigation targets and physical heading only controls heading/glow. With a generated route, **AR Mode** is accessible remotely regardless of demo mode. Opening, minimizing, closing, or reopening AR leaves the physical-walk session and GPS watch running; account/trial and camera checks still apply. AR receives a fresh committed snapshot on handoff, then live progress and heading updates. Rerouting reinitializes the active physical demo on the new geometry and delivers that same new route to AR.

The deterministic engine copies the original route coordinates, computes cumulative metres using the same segment utility as routing, and interpolates committed metres along that polyline. It neither snaps physical GPS to the route nor projects endpoint proximity into arrival. The renderer interpolates route metres, including turns, from the last drawn point; rendering never commits distance. Remaining distance is route length minus committed progress. The explicit demo ETA policy is 1.2m/s, not measured speed. Arrival clamps progress at route length, ends GPS capture, and holds ownership of the dot until End/restart.

The replaceable distance-source contract is `WalkingDistanceSource` / `WalkingDistanceIncrement`. The initial source is the existing movement-evidence filter: only newly accepted displacement from its distance reference becomes an increment, with a session-local sequence for deduplication. Origin capture uses the capture observation as the distance reference. Recovery establishes a new reference without counting the outage gap. The guided mode rejects observations older than 3 seconds. It ends when backgrounded and requires restart/new origin capture, conservatively discarding unobserved movement. Route replacement, selected-point changes, geometry mutation, venue disposal, stop and restart invalidate ownership or session callbacks. No elapsed-time motion is generated.

Diagnostics include raw relative east/north displacement, held/accepted filter decisions, candidate and committed increments, accepted total distance, committed route progress, route length, segment/position, remaining metres, arrival reason, accuracy, age/freshness, mode and a build timestamp fingerprint. Absolute physical latitude/longitude are excluded from the allowlisted export; venue positions remain available. The report's legacy `mode: physical-faithful` envelope is retained for compatibility; `demo.mode` events distinguish individual raw/guided sessions in the same log.

## Estimator assessment

The route engine and synthetic tests establish deterministic distance-to-route behavior. They do **not** establish real walking-distance accuracy in Nigeria. The GPS-derived source still needs physical measurement and improvement: coherent GPS drift can resemble walking; deadbands lose short/slow movement; accepted endpoint chords undercount curved physical paths; interruptions deliberately discard unknown distance. Compare diagnostics against measured stationary, straight, turning, slow-walk and outage trials on actual devices before describing distance as reliable. A validated sensor-based estimator can publish the same sequenced increments without changing route following or rendering.

## Shared 2D and AR authority

The previous AR entry path called `physicalWalk.end()`: it stopped the walking session and restored the normal provider. The demo also updated only the 2D host, so AR was not receiving committed walking progress. AR then used its own GPS/SLAM/extrapolation paths.

`PhysicalWalkNavigation.progressSnapshot` now publishes committed route metres, the position interpolated at those metres, remaining metres, completion, route identity, walking session ID, and accepted-increment sequence. MapApp uses this same snapshot for AR launch, live sync, reopen, and heading-only updates. It retains the single existing 2D renderer and distance estimator. AR sensor warming requests heading only during the demo; provider callbacks and pending sensor starts cannot replace its position ownership. AR sends no independent movement back into the simulation.

`parent-physical-walk` is an explicit AR authority distinct from the time-driven legacy simulator. Physical walking crosses the iframe bridge in one atomic progress message, without a second coordinate packet. The child uses the existing polyline snapping-at-distance, maneuver, ground alignment, arrow mesh, spacing, visibility, and six-arrow density behavior. It neither extrapolates committed distance nor fuses camera translation into progress, starts a GPS watch, or accepts unrelated position packets. Camera/SLAM remains active for world tracking and heading/alignment. Arrival requires the parent's committed completion rather than the child's 5m proximity threshold. Stale route versions, regressing sequences, retired sessions, and unrelated progress streams are rejected. Explicit demo End releases the matching authority; AR close does not.

The 2D dot's existing bounded presentation interpolation is retained. AR consumes the same committed target, rather than the SDK's intermediate drawn position; neither rendering loop creates walking distance. Physical accuracy still requires the field measurements described above.

Resetting the 2D route automatically closes minimized AR through the existing camera/iframe parking path. Ordinary AR open/close still leaves the simulation untouched; an explicit route reset ends the old route session as before.
